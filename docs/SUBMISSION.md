# 提交规范

提交仓库压缩包或私有仓库访问方式，并提供一个固定 commit SHA。通过原招聘私信渠道提交个人材料，不在公开 Issue/PR 提交简历、电话号码、身份证明、密钥或实验室数据。

必须包含 `submission/` 实现、研究报告、原始 predictions JSONL、metrics JSON、运行命令和环境记录，以及至少两个新增测试。报告中的每项结果应能对应到具体输出文件。

可以更新 README、提交文档和新增依赖；不要改写固定开发集、GT 或官方评测器来提高分数。希望改进评测器时请另交明确的补丁与研究说明；正式评分仍用招聘方保存的受信版本。

允许使用 AI 工具，但需披露用途、本人贡献以及检查方式。不能读取评测标签、按样例 ID 查答案、读取未来观测或虚构实验日志。不会因为没有私有 GPU、商用 API 或顶会论文经历扣分。

建议附以下文件：

```text
submission/agent.py
submission/extra_tests.py   # 或 tests/ 中独立新增测试文件
submission/REPORT.md
submission/RUNS.md
submission/AI_USAGE.md
submission/results/...
```

受信环境将重新运行 baseline 和你的实现，不以截图代替原始结果。自定义依赖需写清版本与安装方式；不要提交未获授权的权重或视频。

完成时间为收到题目后的 7 个自然日，净投入建议 6–8 小时、上限 10 小时。达到上限可交部分完成版，清楚说明已验证的内容与卡点。后续以报告讨论与代码走读为主；真实客户项目的额外开发需另行约定。
